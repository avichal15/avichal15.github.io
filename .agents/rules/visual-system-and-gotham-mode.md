# Visual System Rules

- Visual direction: a tactile, LEGO-inspired world combined with purposeful neo-brutalism. Strong typography, visible borders, satisfying hard-edged surfaces and restrained shadows; not a random collage of cards.
- Bricks are a recurring material language. Vary color, lighting, scale or surface detail between project chapters, but keep content contrast and reading comfort high. Do not render thousands of individual brick meshes if a lighter procedural/material solution provides the same visual impression.
- Hero copy must include `Hi, I'm Avichal Goyal` and the approved headline. Avatar initially appears on the right. Maintain clear hierarchy and keep the headline readable at common desktop, tablet and mobile sizes.
- Story sections should feel connected by a persistent character/world; the background and character can morph between chapters rather than abruptly resetting.
- Project pages should show a clear narrative alongside carefully sized desktop/laptop and mobile mockups. Use actual approved project screenshots whenever available. Never fabricate a product UI and present it as a real screenshot.
- Certificate archive cards must be visually distinguishable from projects and expose exact issuer/title; a verification link is visible when available.
- The theme-toggle button should clearly identify the action and support keyboard focus. On activation, transition colors, atmosphere, character variant and playful display treatment coherently; on a second activation return to normal mode.
- Do not globally replace the literal, semantic owner name in DOM, page title, metadata, structured data, resume/certificate details or email address. Any visual name easter egg must be non-destructive and not remove the real identity from accessible text.
- Motion should emphasize the narrative. Avoid constant parallax on all elements, excessive bounce, low-contrast text, flashing, or animations that compete with the project story.
- Use a small set of design tokens for palette, border width, radius, spacing, typography and shadows. Avoid one-off CSS overrides that make the visual language inconsistent.
